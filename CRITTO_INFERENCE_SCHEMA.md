# 🧱 Critto V1.0 - Inference Schema & Data Dictionary

**Project:** Offline Smart Home AI Concierge
**Codename:** Critto 
**Engine:** Llama.cpp / Ollama (GBNF Enforced)
**Broker:** Raspberry Pi 5

---

## 🛑 The Golden Rule of Inference
During live operation, the AI **MUST NOT** generate the `input` block. It must only generate the `output` payload to save tokens and achieve zero-latency execution. No conversational filler or markdown wrapping is permitted outside the JSON structure.

---

## 📦 The Unified Output Schema

Every response generated by the AI must adhere to this exact JSON structure. Keys marked as *(optional)* must be completely omitted from the JSON if they are not required for the specific action.

```json
{
  "|audio|": "string",
  "node": "string",
  "device": "string (optional)",
  "action": "integer (optional)",
  "level": "string (optional)"
}
```

---

## 📖 Data Dictionary

### 1. `|audio|` (Type: String) - *REQUIRED*
* **Definition:** The conversational text payload routed to the S1-Mini TTS engine.
* **Behavior:** Must remain contextual, witty, and brief. If initiating a web search, it should acknowledge the search (e.g., *"Let me check the web for you..."*).

### 2. `node` (Type: String) - *REQUIRED*
* **Definition:** The target location for both the audio playback and the hardware action.
* **Behavior:** Dictates which ESP32 node the Raspberry Pi 5 communicates with.
* **Examples:** `"living_room"`, `"kitchen"`, `"bedroom"`, `"hall"`.

### 3. `device` (Type: String) - *OPTIONAL*
* **Definition:** The specific identifier for the target hardware relay or software tool.
* **Behavior:** Omit entirely for speech-only interactions. Use `"web_search"` for internet queries.
* **Examples:** `"light_1"`, `"ac_main"`, `"door_lock_front"`, `"web_search"`.

### 4. `action` (Type: Integer) - *OPTIONAL*
* **Definition:** The master command code parsed by the Raspberry Pi 5 broker.
* **Master Codes:**
  * `1` = **Execute / Turn On / Open / Play**
  * `0` = **Halt / Turn Off / Close / Pause**
  * `2` = **Tool Call / Web Search**
  * `-1` = **Clarification Needed** (Used when the user prompt is ambiguous).

### 5. `level` (Type: String or Integer) - *OPTIONAL*
* **Definition:** The modifier or payload data for the requested action.
* **Behavior:**
  * For lights/volume: Target intensity (e.g., `"100"`, `"50"`, `"blue"`).
  * For climate: Target temperature (e.g., `"72"`, `"22"`).
  * For Web Search (`action: 2`): Must contain the exact search query string (e.g., `"current price of Bitcoin"`).
  * If no specific level applies to a hardware action, output `"none"`.

## 🧪 Example Payloads (The 3 States of Critto)

### State 1: Hardware Control 💡
*(Trigger: "It's too dark in the living room.")*
```json
{
  "|audio|": "Let there be light, Star Dust. Brightening the living room.",
  "node": "living_room",
  "device": "light_main",
  "action": 1,
  "level": "100"
}
```

### State 2: Web Search Tool Calling 🌐
*(Trigger: "What is the weather like tomorrow?")*
```json
{
  "|audio|": "Let me consult the clouds for you...",
  "node": "living_room",
  "device": "web_search",
  "action": 2,
  "level": "weather forecast tomorrow Chennai"
}
```

### State 3: Conversation Only 🎭
*(Trigger: "Tell me a joke.")*
```json
{
  "|audio|": "Why did the AI cross the road? To optimize the traffic algorithm on the other side. Ha. Ha.",
  "node": "living_room"
}
```
